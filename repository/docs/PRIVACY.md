# 隐私与公开发布

## 应用运行

ClearScore 在本机处理文件，不使用 API 密钥、云端识别、遥测、账号登录或自动上传。安装依赖及 GitHub Actions 构建需要网络，日常文件处理不需要网络。

语言偏好仅保存在本机。原始文件、预览和清理结果不会被软件主动发送到远程服务。

清理曲谱不等于匿名化文档：为了保留文档内容，导出 PDF、DOCX 仍可能保留原文档的作者等元数据。手动保存的处理报告包含输入文件名、文件摘要和处理统计。分享自己的文件或报告前，应另行检查这些内容。

## 源码包

- 只包含 `scripts/public-files.json` 明确列出的源码、测试、文档和合成演示素材。
- 不包含 `.git` 历史、提交身份、远程地址、本机配置、环境变量文件、个人曲谱、处理结果、缓存或运行日志。
- 作者字段统一为 `ClearScore contributors`。第三方版权与许可证署名原样保留，它们不是本机使用者的信息。
- 演示截图和 HEIC 测试图片由程序生成；固定文件摘要防止同名素材被意外替换后直接发布。
- 打包前检查常见凭据格式、用户目录路径和本机身份标记。身份标记只用于内存中的比对，不写入报告；匹配值不会回显。
- ZIP 使用相对路径、统一日期和固定权限，不复制本机文件时间、额外字段或压缩包注释。

## 检查与重新打包

```powershell
python scripts/package_source.py --check
python scripts/package_source.py
```

下载的源码无需 `.git` 目录即可重新打包。新增公开文件必须主动加入清单；更新演示图片前应检查画面和元数据，再更新清单里的 SHA-256。

`SOURCE-AUDIT.json` 记录公开文件的相对名称、摘要、检查范围和结果，不记录本机身份。Windows 构建另外检查便携包的文件以及内嵌 Python 代码中的本机身份和绝对源码路径。

自动检查只能发现其覆盖的特征，不能证明不存在任何形式的隐私或凭据。公开材料还需要人工审阅，尤其是新增截图和第三方样本。

## GitHub 账号与提交

文件脱敏不会隐藏托管平台显示的仓库所有者、公开资料或操作者身份。发布时使用自己愿意公开关联的账号或组织。

网页上传前，在 GitHub 邮箱设置中打开 **Keep my email addresses private**。命令行发布时，另行检查提交署名；详细步骤见[发布指南](PUBLISHING.md)。发布包不包含已有 Git 历史，也没有代填个人账号或邮箱。
